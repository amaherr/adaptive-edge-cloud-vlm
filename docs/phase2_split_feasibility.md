# Pinned Moondream split-boundary inspection

This inspection uses the verified cached Moondream revision `9a7d4024050840e001defacec2b00727e89149e6`, specifically `vision.py`, `moondream.py`, `image_crops.py`, `text.py`, and `config.py` under `.model-cache/audit/moondream2-9a7d4024/`. Those cached model files are pinned by the artifact manifest. The findings identify possible graph boundaries; they do **not** activate another configuration.

| Boundary | Tensor and minimum BF16 payload | Required server work and side inputs | Feasibility status |
| --- | --- | --- | --- |
| Current projected visual features | `(729, 2048)`, 2,985,984 bytes | Image prefill and text model; existing `TENSOR_REQUEST` validates shape/dtype/checksum | Executable and Phase 1 token-equivalent on local CPU. |
| Vision encoder output before crop reconstruction/projector | `(1 + H_tiles × W_tiles, 729, 1152)`, 1,679,616 bytes **per crop**. The 4×4 fixtures use global plus one local crop, about 3,359,232 bytes before framing. | Server needs tiling `(H_tiles, W_tiles)`, crop ordering, reconstruction, adaptive pooling, and projector weights. Edge keeps crop preparation and all 27 encoder blocks. | Worth a round-trip prototype, but larger than the current projected payload for the local fixtures. No payload contract, server handler, partitioned model or equivalence proof exists. |
| After vision encoder block `k` | Same crop-dependent activation shape and bytes as above. | Edge keeps patch embedding, position addition and blocks `0..k`; server needs blocks `k+1..26`, post layer normalization, crop reconstruction and projector. The exact `k`, crop layout and dtype must be encoded. | More substantial partitioning and memory study required. The Python encoder is a loop over blocks with residual updates, so a hook alone does not define a runnable remote continuation. |
| Between text decoder blocks | During prefill, approximately `(1, prompt_length, 2048)` plus position/mask state; during decode one token activation recurs. | Both hosts would need a session protocol for every token and correctly partitioned per-block KV caches. The pinned text decoder has 24 blocks and mutates KV cache state. | Not a V1 candidate. Per-token exchanges and cache ownership need a new protocol and correctness proof. |

The crop count is image dependent and can reach one global crop plus up to 12 local crops under the pinned tiling algorithm. The vision encoder output therefore ranges up to about 21.8 MB before metadata and framing. The local 4×4 fixtures exercise only the smallest two-crop case; they cannot establish general payload or memory safety. The present `ProjectedVisionFeatures` contract assumes `(729, 2048)` and BF16; reusing its type or current `TENSOR_REQUEST` for another tensor would misrepresent the protocol.

Promotion of a new boundary requires a versioned tensor/side-input contract, exact tensor round-trip checks, partitioned edge/cloud loading with measured resident and peak memory, a server capability and handler, end-to-end token equality on the frozen correctness manifest, failure/timeout handling, and the same profile coverage and network conditions as the three baseline choices. Until that evidence exists, the registry remains the three executable candidates from Phase 1.
