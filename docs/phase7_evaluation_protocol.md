# Phase 7 evaluation protocol

Frozen on 2026-10-26 before running the Phase 7 analysis command. The accompanying machine-readable local specification is [`configs/evaluation/phase7_local_diagnostic.json`](../configs/evaluation/phase7_local_diagnostic.json). The existing Phase 2–6 observations and Phase 3 holdout have already been inspected, so this local analysis is **retrospective and descriptive**. It cannot satisfy the independent thesis gate.

## Primary prospective campaign

Freeze a new specification, manifest, calibration, replay, and run order **before** collecting outcomes on the second host. Use one pinned Moondream model revision, precision, prompt template, generation cap, image preprocessing path, and three placements across all methods. The existing 32-new-token contract is the only supported contract today. Any 100/300-token study needs its own model contract, equivalence run, profiles, calibration, and analysis; do not pool the campaigns. Import an official VQA v2 val2014 subset with `import-vqa-v2` after the official question, annotation, and COCO image files are available. Keep at least one separately frozen short-answer task and, if the model and budget support it, a descriptive task. Declare each task bucket and its expected output length estimator from training data before inference; prompt token count and source/task type must be determined from the input only. Do not condition a decision on generated output length.

Use disjoint request IDs for calibration training, validation static-policy choice, and evaluation. Also hold out complete controlled network blocks from calibration and threshold selection. Declare the host pair and actual uplink/downlink/RTT measurement source. Run always-edge, always-cloud, fixed projected split, and adaptive on the same randomized request order within each network block; rotate policy order between blocks. Keep one warmup per policy/block, then at least three measured repetitions per request/policy/block. Record model residency, device placement, thermal/load conditions, memory budget and measured peak, and any rejected trial with its reason. Retain failed/timeout/OOM rows in every denominator. A disconnected or unsupported configuration remains an observed failure or explicit ineligibility, never a silently dropped case.

The primary latency comparison is paired per trial and block. Report successful median and nearest-rank p95 latency, SLA success among **all** measured trials, mean application wire bytes per successful trial and per attempted trial, measured edge memory peak, selection and monitoring overhead, decision distribution, and failures by status. Declare one SLA before running (60 seconds in the local diagnostic). Choose best-static on validation IDs using highest SLA success, then lowest median successful latency, then the fixed order edge/cloud/distributed. Fix that choice before evaluating held-out IDs. The measured oracle is the fastest *successful* fixed control for the same trial; report adaptive minus oracle latency only where both exist, plus coverage/failure counts. This is hindsight measured regret, not an achievable online target. Bootstrap request/block clusters together with a fixed seed for paired mean latency differences and their 95% percentile intervals. Report raw pair count and request/block cluster count; do not interpret a tiny interval as independent evidence.

For VQA accuracy, export answer predictions and run the official VQA v2 evaluation code against the matching official annotations/questions. The official loader requires a result for every annotation ID, so create a matching subset with `prepare-vqa-eval-subset`; `export-vqa-predictions` emits empty answers for failed trials. The committed `scripts/run_official_vqa_eval.py` adapter records the evaluator source hashes and output. The upstream evaluator uses Python 2 syntax and needs a compatible environment. The runner's `quality_score` for `vqa_consensus` is provisional and must never be labeled official accuracy. Exact token equality between placements of the same model is an equivalence result. A quality floor is only meaningful after a separately validated optimization changes quality. Energy is omitted unless a sensor, calibration, sampling window, idle subtraction, and host boundary are declared.

## Local retrospective diagnostic

The current archived WSL CPU/loopback campaign has one measured repetition for 12 synthetic `correctness-*` requests; it has no official VQA labels and no controlled network blocks. The three fixed runs and adaptive run were collected at different times without randomized policy order. Replay health exclusions force four adaptive choices per placement. The Phase 3 calibration trained on IDs 001–010 and its two held-out IDs 011–012 were inspected during prior phases. This protocol uses IDs 001–010 only to choose best-static and reports 011–012 only for the descriptive paired evaluation. No prospective confidence or physical-network performance conclusion is permitted. The local report remains useful to verify complete provenance, failure accounting, report generation, and second-host wiring.

The local specification pins the manifest/model/calibration hashes, 60,000 ms SLA, nearest-rank p95, request-cluster bootstrap seed 1707 and 2,000 resamples. The report command refuses missing trials, mismatched schedules/model/manifest/config, duplicate rows, evaluation IDs overlapping either training or validation, and run rows with inconsistent plan hashes. Prospective campaigns additionally require training and validation IDs to be disjoint. It emits a JSON report and paired raw table with file hashes. Raw trial files and their source archives remain in `artifacts/`.

## G7 pass conditions

All frozen task/network cases must have archived raw rows, hashes, verified hardware and controlled-network records, complete failure accounting, official VQA output for the VQA subset, and a reproducible paired report. A fresh evaluation split and independent network blocks must be disjoint from all fitting/selection inputs. G0 physical, G3 ranking, G4 safety/regret, G6 physical sensing, and the official-data campaign must pass before a full G7 claim. A measured negative result is acceptable; incomplete coverage is not.
